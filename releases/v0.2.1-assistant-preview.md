Response-format hotfix and diagnostics. **Pre-release**, not a stable release.

### Why this update

User testing confirmed ChatGPT sign-in, but a conversation using GPT-6 Luna failed with "OpenAI không trả về luồng hội thoại hợp lệ." The old code stopped when a successful HTTP response's Content-Type did not start with `text/event-stream`, hiding the response shape and any structured error. The original status, MIME, request ID and body were not captured, so the underlying server response is still unknown.

### Changes

- Explicitly request `Accept: text/event-stream` while retaining `stream:true` and `store:false`.
- Normalize MIME type and accept genuine SSE with a missing or nonstandard MIME. Still require `response.completed`; partial streams, HTML and plain JSON are not accepted as successful answers.
- Classify non-stream responses and display known OpenAI error codes as actionable messages, including errors inside a failed stream.
- Add **Chi tiết lỗi / Phản hồi hội thoại** with a copy action for HTTP status, normalized media type, body-shape category, recognized error code and request ID. No raw body, prompts, answers, email, tokens or authorization headers are included.
- Keep the selected model and existing sign-in/storage unchanged. No automatic retries or alternate billing route.

### Try it

Install over v0.2.0; do not clear app data. Keep the current ChatGPT account and GPT-6 Luna selection. Try one short typed question. If it still fails, open **Chi tiết lỗi / Phản hồi hội thoại**, copy the details and send them for diagnosis.

This fixes header handling and hidden-error reporting. It does not establish the cause of the original on-device failure or prove successful inference on the user's account. Audio, camera and gesture support have the same limits as v0.2.0.

See [assistant setup](https://github.com/Spotlighterr/XiaomiGpt/blob/main/docs/ASSISTANT_PREVIEW_v1.md) and [official error guidance](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).
